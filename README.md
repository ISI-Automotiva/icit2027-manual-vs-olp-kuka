# Manual vs. offline-programmed KUKA KR 60-3 program: physical acquisitions

Data and analysis script for the paper *Manual Versus Offline Robot Programming on a Physical Robot: Cycle Time and Axis Torque* (Instituto SENAI de Inovação para Tecnologias da Informação e Comunicação, submitted to IEEE ICIT 2027).

**License:** all files are released under [CC BY 4.0](LICENSE).

## Contents

| Path | Description |
|---|---|
| `brutos/OP1_100_lote001_100ciclos.csv` | P1 (manual KRL), 100 % speed setting, 100 cycles |
| `brutos/OP1_75_lote001_100ciclos.csv` | P1, 75 % |
| `brutos/OP1_SIM_100_lote001_100ciclos.csv` | P1_SIM (offline, Siemens Process Simulate), 100 % |
| `brutos/OP1_SIM_75_lote001_100ciclos.csv` | P1_SIM, 75 % |
| `brutos/SHA256SUMS` | Checksums of the four files (`sha256sum -c SHA256SUMS`) |
| `analise.py` | Recomputes every result of the paper and the data figures |
| `resultados/numeros.json` | Output of `analise.py`: all computed values, per condition and per axis |
| `figures/` | Data figures generated by `analise.py`. Figs. 3, 4, and 5 of the paper are `fig_tcp_path.pdf`, `fig_torque_tempo.pdf`, and `fig_resultados.pdf`. `fig_ciclos.pdf` and `fig_torque_ciclo.pdf` are supplementary views of the same data. |

All four files were recorded on 13-Oct-2026 from a KUKA KR C5 controller over TCP/IP. Each file holds one acquisition of 100 consecutive cycles.

## File format

UTF-8 CSV with BOM, comma-separated, 112 columns, one row per sample.

- **Program and event fields:** `timestamp` (PC clock, ISO 8601), `tempo_execucao` (monotonic execution-time field of the logger, s; its increments equal `sample_dt_s`), `programa`, `estado_programa`, `modo_programa`, `arquivo_src`, `bloco_main`, `bloco_advance`, `ponto`, `executado`, `cycle_id`, `cycle_completed_total`, `cycle_event`, `movement_id`, `batch_number`, `batch_cycle`.
- **TCP fields:** `TCP_{X,Y,Z,A,B,C}_{set,meas}`, `TCP_position_error_mm`, `TCP_speed_m_s`, `TCP_acc_{X,Y,Z,abs}_m_s2`, `distance_mm`, `distance_next_mm`.
- **Settings:** `override_program_pct`, `override_robot_pct`, `tool_id`, `base_id`, `payload_kg`, `approx_cdis_mm`, `approx_cptp_pct`, `approx_cvel_pct`, `gear_jerk_pct`, `robot_runtime_min`.
- **Logger quality:** `sample_dt_s`, `read_time_ms`, `jitter_ms`, `overrun`, `read_errors`, `sample_quality`.
- **Per axis (`A1`–`A6`, 10 columns each):** `_setpoint_deg`, `_measured_deg`, `_position_error_deg`, `_speed_pct`, `_current_pct`, `_torque_Nm`, `_torque_max_Nm`, `_torque_usage_pct`, `_follow_error_ms`, `_motor_temp_K`.

Some columns, such as `*_torque_max_Nm` and `*_motor_temp_K`, are written only at the start of an acquisition. Empty cells are therefore expected.

## Known caveats

- **Cycle boundaries:** `cycle_event == "CYCLE_END"` marks each cycle completion, which gives 99 completion-to-completion intervals per file.
- **Time base:** use `tempo_execucao`. In `OP1_75`, the PC `timestamp` steps back by 2.75 s during cycle 88.
- **Sampling:** the median sampling interval is 0.26–0.27 s, and every sample has `sample_quality = WARN` and `overrun = 1`. Peak values are therefore sampled peaks.
- **Torque channels:** the column names are the labels exported by the acquisition software. The `*_torque_Nm` columns follow scaled motor current; their source variable and unit are not confirmed, so the paper uses only relative changes within the same channel and axis.

## Reproduce

```bash
python -m pip install -r requirements.txt
python -I analise.py   # ends with "OK: todos os asserts passaram"
```

Tested with Python 3.14.5. The script verifies the checksums before reading the data. Its comments are in Portuguese.
